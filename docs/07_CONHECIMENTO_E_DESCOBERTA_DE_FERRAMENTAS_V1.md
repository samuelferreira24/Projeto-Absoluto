# Conhecimento e descoberta de ferramentas — ABS V1

O ABS não deve apenas possuir conectores. Ele precisa construir conhecimento operacional sobre os recursos que utiliza.

## Ciclo

DESCOBRIR → IDENTIFICAR → PESQUISAR → CATALOGAR → VALIDAR → CONECTAR → EXPERIMENTAR → REGISTRAR EVIDÊNCIA → APRENDER → ATUALIZAR CONHECIMENTO → USAR / COMBINAR → REAVALIAR

### Estados epistemológicos

- discovered: encontrado, ainda não validado.
- catalogued: conhecido no catálogo inicial.
- validated: uso/contrato validado por evidência.
- operational: caminho operacional comprovado.
- degraded: disponível com limitações.
- retired: não deve mais ser usado como caminho atual.

Um catálogo não é prova de operação.

## Conhecimento de ferramenta

Cada ferramenta pode acumular capacidades, caminhos de conexão, contrato de entrada, contrato de saída, limitações, padrões de uso, evidências, lições aprendidas e metadados.

Isso permite que o ABS aprenda como usar uma ferramenta sem confundir isso com treinamento do modelo.

## Descoberta aberta

Novas ferramentas podem entrar por pesquisa na Internet, indicação do Imperador, documentação/API, novos conectores, descoberta durante uma missão, novos dispositivos, novas tecnologias ou novas redes.

A descoberta cria uma candidata. Não instala nem autoriza automaticamente.

## Regra

NOVA FERRAMENTA → descoberta → pesquisa → validação → conexão → experimento → evidência → conhecimento → roteamento

Assim, o universo de ferramentas do ABS permanece aberto e substituível.
