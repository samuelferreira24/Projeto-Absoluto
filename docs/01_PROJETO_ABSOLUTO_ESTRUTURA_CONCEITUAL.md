# Estrutura Conceitual do Projeto Absoluto — V0.1

## 1. Finalidade

Este documento registra a distinção conceitual usada para organizar o Projeto Absoluto.

O Projeto Absoluto é o projeto maior: a visão, o método, os princípios, os objetivos e a direção que o Imperador pretende transformar em realidade.

O Sistema não é o próprio Projeto Absoluto. O Sistema é uma peça criada para aumentar a capacidade de transformar a visão em execução.

O ABS é, neste estágio, o primeiro grande projeto prático que está sendo construído dentro do Projeto Absoluto.

## 2. Modelo atual

```
PROJETO ABSOLUTO
│
├── VISÃO
├── MÉTODO
├── PRINCÍPIOS
├── OBJETIVOS
├── CONHECIMENTO / APRENDIZADO
│
├── SISTEMA
│   └── infraestrutura para pesquisar, aprender,
│       planejar, construir e executar
│
├── PROJETOS
│   └── ABS — primeiro projeto em construção
│
├── FUTUROS PROJETOS
│
└── IMPÉRIO
```

Esta representação é conceitual. A estrutura física de repositórios e pastas não precisa reproduzi-la literalmente.

## 3. O papel do Imperador

O Imperador mantém a autoridade humana sobre visão, direção, decisões e autorização.

A IA e as ferramentas são meios. Podem ser substituídas, combinadas ou abandonadas conforme a necessidade.

O Projeto Absoluto não pressupõe que o Imperador já saiba implementar tudo o que imaginou.

Parte do próprio método é aprender enquanto constrói.

## 4. O papel do Sistema

O Sistema existe para ampliar a capacidade de construção.

Ele deve ajudar a:

- pesquisar;
- aprender;
- organizar conhecimento;
- descobrir ferramentas e caminhos;
- planejar;
- construir;
- testar;
- executar;
- registrar resultados;
- preservar continuidade;
- aprender com erros e experiências;
- aumentar progressivamente a capacidade de realizar novos projetos.

Portanto, o Sistema é meio e infraestrutura, não o objetivo final.

## 5. O papel do ABS

O ABS é o primeiro projeto que está sendo efetivamente construído a partir dessa visão.

O ABS pode utilizar o Sistema e também contribuir para sua evolução.

Construir o ABS produz aprendizado sobre como construir sistemas, ferramentas e projetos maiores.

O ABS V1 é o segundo protótipo do ABS. Ele não representa a forma definitiva do ABS.

## 6. Aprender enquanto constrói

O Projeto Absoluto deve aceitar explicitamente que a implementação é parcialmente desconhecida no início.

O ciclo real é:

```
VISÃO
  ↓
IDEIA
  ↓
NECESSIDADE / PERGUNTA
  ↓
PESQUISA
  ↓
APRENDIZADO
  ↓
HIPÓTESE
  ↓
CONSTRUÇÃO
  ↓
TESTE
  ↓
RESULTADO
  ↓
CAPACIDADE / CONHECIMENTO
  ↓
NOVA VISÃO DE POSSIBILIDADES
  ↺
```

Isso significa que documentação futura não deve apresentar como arquitetura definitiva aquilo que ainda é hipótese ou aprendizado em andamento.

## 7. Fonte conceitual

Os arquivos-base históricos do Projeto Absoluto são fontes importantes para reconstruir a visão, o método, os princípios, os objetivos e a origem das ideias.

Eles não devem ser tratados automaticamente como especificações técnicas atuais do ABS.

Quando houver conflito entre uma ideia histórica dos arquivos-base e uma decisão posterior explicitamente tomada pelo Imperador, a decisão posterior deve ser registrada como decisão atual, preservando a fonte histórica.

A organização deve preservar o conteúdo original, sem transformar os arquivos-base em um simples resumo.

## 8. Regra de organização

A organização deve responder separadamente:

1. O que o Projeto Absoluto quer realizar?
2. O que já foi decidido?
3. O que ainda é ideia ou hipótese?
4. O que estamos aprendendo?
5. O que é o Sistema?
6. Qual projeto está sendo construído?
7. O que já funciona?
8. Qual evidência comprova?
9. O que pertence ao histórico?
10. Qual é o próximo ponto de continuidade?

Não devemos organizar o projeto apenas pela tecnologia usada para construí-lo.

## 9. Regra para evolução

A estrutura atual não deve impedir projetos futuros.

Um novo projeto pode:

- usar o Sistema;
- usar o ABS;
- usar somente algumas capacidades;
- criar infraestrutura própria;
- substituir componentes existentes;
- ou posteriormente tornar-se parte de uma estrutura maior.

A arquitetura deve permitir crescimento sem transformar o estado atual em uma prisão.

## 10. Relação com a arquitetura de informação

Esta definição antecede a classificação física dos documentos.

Antes de mover, fundir ou arquivar documentos, devemos classificá-los por:

- função;
- autoridade;
- temporariedade;
- origem;
- público;
- relação com Projeto Absoluto, Sistema ou projeto específico.

Nenhum documento deve ser movido apenas para deixar a árvore visualmente mais bonita.

## 11. Estado da decisão

**Status:** decisão conceitual atual.

**Não é:** especificação técnica definitiva.

**Não altera:** a visão original dos arquivos-base.

**Serve para:** orientar a reorganização documental, a continuidade e a separação entre visão, Sistema e projetos.

---

> Princípio central:
>
> **O Projeto Absoluto é a visão e o projeto maior. O Sistema é uma peça criada para aumentar a capacidade de realizá-lo. O ABS é o primeiro projeto em construção. E o conhecimento necessário para construir tudo isso é adquirido progressivamente enquanto construímos.**
