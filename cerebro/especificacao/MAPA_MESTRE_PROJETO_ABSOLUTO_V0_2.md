# MAPA MESTRE DO PROJETO ABSOLUTO V0.2

## 1. Natureza deste mapa

Este documento é um **quadro mestre de planejamento e construção**, não uma especificação definitiva do Projeto Absoluto.

Ele registra o entendimento atual do Projeto, suas capacidades, hipóteses arquiteturais, o que já foi construído, o que está sendo construído, o que ainda precisa ser pesquisado e as possibilidades futuras.

O mapa deve evoluir junto com o Projeto.

> Planejamento e construção acontecem simultaneamente. A construção produz experiência; a experiência modifica o planejamento; o novo planejamento orienta a próxima construção.

---

## 2. Princípio central

O Projeto Absoluto não deve ser reduzido a IA, software, automação, GitHub, Cérebro ou qualquer tecnologia específica.

Esses elementos são **meios, componentes e engrenagens** que podem ser substituídos, combinados ou ampliados.

A arquitetura deve permanecer aberta para incorporar tecnologias, agentes, sistemas e capacidades que ainda não existem ou ainda não foram escolhidos.

---

## 3. Visão temporal

O Projeto é construído olhando simultaneamente para três dimensões:

```text
PASSADO                 PRESENTE                 FUTURO
  │                       │                       │
  │ compreender           │ construir             │ planejar
  │ reconstruir           │ registrar             │ antecipar
  │ recuperar             │ experimentar         │ projetar
  │ aprender              │ aplicar               │ evoluir
  └───────────────┬───────┴────────┬──────────────┘
                  │                │
                  ▼                ▼
               CÉREBRO ───────► PRÓXIMO CICLO
```

O Projeto deve conseguir reconstruir como chegou ao estado atual, compreender o presente e utilizar ambos para orientar o futuro.

# 6. O CÉREBRO COMO PARTE DA CONSTRUÇÃO ATUAL

O Cérebro não deve ser construído primeiro para só depois ser utilizado.

Ele já deve participar do próprio processo de construção.

```text
PESQUISA ──────────────┐
CONTEXTO ──────────────┤
DECISÕES ──────────────┤
ERROS ────────────────┤
CORREÇÕES ────────────┤
EXPERIÊNCIAS ─────────┤──► CÉREBRO
RESULTADOS ───────────┤       │
APRENDIZADOS ─────────┤       ▼
SABEDORIA ────────────┘  NOVO PLANEJAMENTO
                              │
                              ▼
                         NOVA CONSTRUÇÃO
                              ↺
```

Portanto, o Cérebro deve guardar não somente conhecimento externo, mas também o **conhecimento de como o próprio Projeto está sendo construído**.

# 7. UNIDADES DE MEMÓRIA DO PROJETO

A estrutura futura deve distinguir pelo menos:

```text
FONTE
  ↓
INFORMAÇÃO
  ↓
INTERPRETAÇÃO
  ↓
CONHECIMENTO
  ↓
DECISÃO
  ↓
AÇÃO
  ↓
RESULTADO
  ↓
EXPERIÊNCIA
  ↓
APRENDIZADO
  ↓
SABEDORIA
```

Cada camada deve manter sua origem e contexto.

Uma interpretação de uma IA não deve automaticamente virar fato.

Uma hipótese não deve automaticamente virar conhecimento validado.

Uma experiência isolada não deve automaticamente virar regra universal.

---

# 8. MEMÓRIA TEMPORAL

O Cérebro deve evoluir de uma simples memória de itens para uma memória de **trajetórias**.

Ele precisa responder, progressivamente:

- O que aconteceu?
- Quando aconteceu?
- Em qual contexto?
- Quem/qual agente participou?
- O que sabíamos naquele momento?
- O que acreditávamos naquele momento?
- Qual decisão foi tomada?
- Por que foi tomada?
- O que foi feito?
- Qual foi o resultado?
- Qual evidência surgiu depois?
- O que mudou?
- O que aprendemos?
- O que continua válido?
- O que foi superado?
- O que devemos fazer agora?

# 10. FUTURA ARQUITETURA DE VÁRIAS IAs

A ideia de várias IAs é uma **hipótese de planejamento**, não uma definição final.

Possível estrutura:

```text
                         PROJETO
                            │
                         CÉREBRO
                            │
                     ORQUESTRAÇÃO
                            │
          ┌─────────────────┼─────────────────┐
          ▼                 ▼                 ▼
       IA-A              IA-B              IA-C
      pesquisa          execução          análise
          │                 │                 │
          └─────────────────┼─────────────────┘
                            ▼
                       SUPERVISÃO
                            │
                       AUDITORIA
                            │
                       RESULTADO
                            │
                         CÉREBRO
```

No futuro, isso pode evoluir para uma rede dinâmica na qual agentes:

- recebem tarefas;
- delegam tarefas;
- supervisionam outros agentes;
- contestam resultados;
- verificam evidências;
- formam equipes temporárias;
- mudam de função conforme a necessidade;
- operam continuamente dentro de permissões e limites.

Nada disso deve ser tratado como arquitetura definitiva antes de pesquisa, prototipagem e validação.

---

# 11. CONTINUIDADE ENTRE IAs

A continuidade não pode depender da memória de uma conversa ou de uma IA específica.

```text
                CONHECIMENTO DO PROJETO
                         │
       ┌─────────────────┼─────────────────┐
       ▼                 ▼                 ▼
     IA A              IA B              IA C
       │                 │                 │
       └─────────────────┼─────────────────┘
                         ▼
                      PROJETO
```

Uma nova IA deve poder reconstruir o contexto a partir de artefatos do Projeto:

1. visão;
2. princípios;
3. método;
4. arquitetura atual;
5. estado;
6. histórico;
7. decisões;
8. evidências;
9. testes;
10. problemas;
11. aprendizados;
12. próximos objetivos.

---

# 12. GITHUB E OUTRAS TECNOLOGIAS

GitHub é um meio de controle, versionamento e colaboração da construção atual.

Não é a identidade completa do Projeto.

O mesmo princípio vale para:

- ChatGPT;
- outras IAs;
- bancos de dados;
- APIs;
- automações;
- servidores;
- ferramentas;
- plataformas externas.

O Projeto deve manter sua identidade, conhecimento, histórico, contratos e contexto de forma que mudanças tecnológicas não destruam sua continuidade.

# 14. PRIORIDADE DE CONSTRUÇÃO ATUAL

A próxima etapa não deve ser escolhida simplesmente por ser a próxima linha da tabela.

A prioridade deve ser determinada por:

```text
IMPACTO
+ DEPENDÊNCIAS
+ RISCO
+ INCERTEZA
+ VALOR DE APRENDIZADO
+ CAPACIDADE DE DESBLOQUEIO
+ CUSTO
+ REVERSIBILIDADE
```

Isso evita construir componentes sofisticados antes de existir a estrutura necessária para utilizá-los corretamente.

# 17. O QUE AINDA É DESCONHECIDO

O mapa deve manter uma área explícita para desconhecidos.

Não devemos fingir conhecer hoje:

- a forma final do Cérebro;
- a forma final da IA do usuário;
- a arquitetura final de multi-IA;
- a tecnologia final de integração;
- o nível final de automação;
- a escala futura;
- todas as capacidades que o Projeto poderá adquirir.

O desconhecido é uma categoria legítima do planejamento.

---

# 19. PRINCÍPIO FINAL

> **Estamos planejando e construindo ao mesmo tempo.**
>
> O planejamento orienta a construção.
> A construção produz experiência.
> A experiência alimenta o Cérebro.
> O Cérebro preserva conhecimento e história.
> O aprendizado modifica o planejamento.
> A sabedoria orienta novas decisões.
> E cada ciclo prepara o Projeto para o próximo nível.

Portanto, o objetivo desta versão do mapa não é prever todo o Projeto Absoluto.

É criar uma visão suficientemente ampla para **não limitar o futuro**, e suficientemente estruturada para **permitir construir o próximo passo agora**.
