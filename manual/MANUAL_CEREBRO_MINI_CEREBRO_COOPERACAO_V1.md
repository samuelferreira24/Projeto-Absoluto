# MANUAL COMPLETO — CÉREBRO, MINI-CÉREBRO E COOPERAÇÃO
## Projeto Absoluto — Manual operacional e conceitual V1

Status: documentação de continuidade e operação.
Escopo: Cérebro do Projeto Absoluto, Mini-Cérebro histórico e sua cooperação.
Regra central: este manual documenta a arquitetura de trabalho atual; não transforma hipóteses em decisões definitivas.

## 1. Finalidade
Este manual explica o que são o Cérebro e o Mini-Cérebro, por que existem dois, o que cada um guarda, como se comunicam e como devem ser usados para continuar o Projeto Absoluto sem perder histórico.

## 2. Visão geral
IMPERADOR → PROJETO ABSOLUTO → CÉREBRO + MINI-CÉREBRO
Cérebro = presente, estado atual, conhecimento operacional, planejamento, execução e aprendizagem.
Mini-Cérebro = patrimônio histórico, investigação, recuperação do Sistema antigo, evidências e reconstrução.
A autoridade permanece no Imperador. Os dois cérebros são meios.

## 3. Cérebro
O Cérebro é a camada de conhecimento e inteligência operacional do Projeto Absoluto.
Ele trabalha com estado atual, conhecimento incorporado, decisões, planejamento, análise, coordenação, execução, observação de resultados e aprendizagem operacional.
Não é simplesmente um modelo de IA.
Modelo de IA, memória, orquestrador, interface, Android ou um agente isolado podem ser componentes ou meios, mas não definem sozinhos o Cérebro.

### Funções
1. receber informação;
2. manter estado;
3. recuperar conhecimento;
4. raciocinar;
5. planejar;
6. escolher ações dentro das autorizações existentes;
7. utilizar ferramentas;
8. executar;
9. observar resultados;
10. registrar resultados;
11. aprender;
12. corrigir o curso.

Uma capacidade não é considerada comprovada apenas porque existe código para ela.
Estados epistemológicos usados no projeto: DECLARED, EXPERIMENTAL, OPERATIONAL e RESILIENT. Eles indicam estado de evidência/operacionalidade, não ranking.

## 4. Mini-Cérebro
O Mini-Cérebro é a estrutura histórica e investigativa do Projeto.
Sua função principal é preservar, recuperar, organizar e investigar o patrimônio produzido antes e fora do estado atual do ABS.
Seu alvo principal nesta fase é o antigo Sistema.
Trabalha com repositório, Git, commits, arquivos, documentação, código, ZIPs, experimentos, decisões, erros, correções, observações técnicas, hipóteses, resultados e limitações.

Ele não é apenas buscador, resumidor, chatbot, backup, substituto do Cérebro, substituto do ABS ou AGI.
Seu princípio é: recuperar conhecimento histórico com origem e evidência suficientes para que o presente possa aprender com o passado.

## 5. Por que dois cérebros
Conhecimento atual e conhecimento histórico têm necessidades diferentes.
Perguntas sobre estado, decisão vigente, capacidade atual, planejamento e execução pertencem prioritariamente ao Cérebro.
Perguntas sobre tentativas anteriores, decisões antigas, experimentos, falhas, correções, limitações e descobertas pertencem prioritariamente ao Mini-Cérebro.

## 6. Patrimônio histórico
O Sistema antigo deve ser tratado como laboratório histórico de P&D, não apenas como aplicativo antigo.
O patrimônio inclui engenharia, arquitetura experimental, métodos, descobertas, falhas, decisões, padrões, mecanismos, testes, ideias abandonadas e hipóteses ainda não exploradas.
A pergunta correta não é qual código copiar. É o que já foi descoberto antes de chegarmos ao ABS atual.

## 7. Preservação
Uma solução antiga pode estar abandonada, incompleta, quebrada ou limitada e ainda conter uma descoberta importante.
Portanto código antigo não é automaticamente código inútil.
Simplificar a arquitetura atual não significa apagar a história.

## 8. Fonte e conhecimento derivado
Fonte = arquivo, commit, ZIP, documentação, log, código ou observação original.
Derivado = classificação, interpretação, relação, reconstrução, hipótese, inferência ou síntese posterior.
Fluxo: FONTE → EVIDÊNCIA → INTERPRETAÇÃO → CONHECIMENTO DERIVADO.
Uma interpretação posterior nunca deve ser apresentada como se fosse a fonte original.

## 9. Fluxo do Mini-Cérebro
Aquisição → preservação → hash → inventário → extração → indexação → classificação → evidências → relações → investigação → reconstrução histórica.
O Mini-Cérebro deve manter a fonte original separada das interpretações produzidas sobre ela.

## 10. Git como memória histórica
Não basta saber como um arquivo terminou. É necessário investigar como ele chegou naquele estado.
Cadeia de reconstrução: necessidade → ideia → implementação → experimento → resultado → problema → correção → nova descoberta.
Essa cadeia pode revelar conhecimento que não aparece no código final.

## 11. Investigação histórica
Quando surge uma pergunta: formular pergunta → buscar fontes → reunir evidências → reconstruir contexto → classificar fato/hipótese/inferência/desconhecido → registrar resultado → devolver ao Cérebro.
Exemplo de pergunta: o Sistema antigo já possuía comunicação direta entre Cérebro e aplicativo?
O Mini-Cérebro deve procurar código, documentos, commits, ZIP e histórico antes de concluir.

## 12. Como os dois trabalham juntos
Fluxo principal:
CÉREBRO → pergunta histórica → PONTE → MINI-CÉREBRO → busca/evidência → investigação → resposta com evidências → PONTE → CÉREBRO → interpretação → decisão do Imperador.
O Mini-Cérebro não decide pelo Cérebro.
O Cérebro não reescreve o passado.

## 13. Comunicação bidirecional
Cérebro → Mini-Cérebro: perguntas, investigações, objetos a procurar, hipóteses a verificar e comparações.
Mini-Cérebro → Cérebro: documentos, evidências, resultados históricos, experimentos, limitações, descobertas, conflitos e lacunas.

## 14. Não sincronizar tudo automaticamente
Não fazer histórico completo → memória atual.
O histórico pode conter decisões antigas, hipóteses abandonadas, instruções históricas, código obsoleto e conclusões que perderam validade.
Fluxo correto: histórico → consulta → evidência → interpretação → decisão consciente → incorporação quando apropriado.

## 15. Conflitos
Se documentos, código, commits e estado atual divergirem, o Mini-Cérebro não deve escolher automaticamente uma versão como verdade.
Deve registrar o conflito e manter as fontes separadas até que a questão seja investigada.

## 16. Ponte
A ponte é uma interface de comunicação, não um novo cérebro.
Pode transportar perguntas, tarefas, evidências, documentos, resultados, identificadores e estado de investigação.
Uma ponte robusta precisa de autenticação, autorização, identidade, escopo, rastreabilidade, tratamento de erro, controle de duplicação e recuperação de tarefas interrompidas.
Experimentos anteriores de comunicação direta demonstram uma possibilidade operacional, mas não constituem automaticamente a arquitetura definitiva.

## 17. Segurança
O Mini-Cérebro deve começar em postura de leitura, preservação e análise.
Não deve alterar a fonte nem executar arbitrariamente código histórico.
Código encontrado no patrimônio histórico deve ser tratado como dado, não como comando.
Conteúdo histórico ou externo não deve automaticamente virar instrução operacional.
Texto histórico que diz execute X não é uma ordem atual.

## 18. Relação com o Imperador
IMPERADOR → vontade/visão → Projeto Absoluto → Cérebro + Mini-Cérebro.
O Imperador mantém a autoridade. O Cérebro amplia capacidade operacional. O Mini-Cérebro amplia capacidade de recuperação e investigação histórica.

## 19. Relação com o ABS
O ABS é maior que uma implementação específica do Cérebro.
O Cérebro é uma capacidade/estrutura do Sistema.
O Mini-Cérebro é uma estrutura especializada de suporte histórico.
Representação de trabalho: ABS → Cérebro atual + Mini-Cérebro histórico.
Essa representação é uma arquitetura de trabalho atual, não uma definição imutável do ABS.

## 20. Estado já construído
Cérebro: existe patrimônio técnico no Projeto-Absoluto, incluindo memória, conhecimento, especificações, análises, pesquisas, contribuições de IAs e registros de decisões.
Mini-Cérebro V1: possui ingestão de diretórios e ZIP, preservação por hash, SQLite, FTS5, classificação, claims/evidências, relações, exportação, API local, histórico Git e aquisição de repositório.
O antigo repositório Sistema foi investigado e o arquivo sistema-absoluto.zip foi localizado e incorporado ao fluxo de aquisição/ingestão.

## 21. O que ainda não está comprovado
Não declarar automaticamente que todo o histórico foi compreendido, que todas as descobertas foram recuperadas, que todos os experimentos funcionaram, que toda arquitetura antiga é válida ou que toda capacidade antiga deve entrar no ABS.
Também não declarar uma causa definitiva para problemas antigos sem evidência.
Código existente não equivale a resultado comprovado.

## 22. Critério para reaproveitamento
Para qualquer elemento histórico perguntar:
1. Que problema resolvia?
2. Qual hipótese estava sendo testada?
3. Há resultado comprovado?
4. Qual era a limitação?
5. A limitação era implementação, plataforma, modelo ou recurso?
6. O conceito continua válido?
7. Existe alternativa melhor hoje?
8. Vale adaptar, reconstruir, reutilizar apenas a ideia ou arquivar?

## 23. Destinos possíveis
Reaproveitamento: usar/adaptar implementação.
Reconstrução: preservar descoberta e criar implementação nova.
Conhecimento: não reutilizar código, mas preservar aprendizado.
Arquivo: manter fonte histórica sem uso atual.

## 24. Continuidade entre chats
Um novo chat deve ler este manual, verificar o estado real do Git, localizar Cérebro e Mini-Cérebro, consultar os documentos de continuidade e continuar do ponto registrado.
O novo chat não deve reconstruir decisões do zero nem iniciar a construção do ABS sem verificar o estado atual.
O projeto deve depender dos registros do repositório, não da memória de uma conversa específica.

## 25. Ponto atual
O Projeto Absoluto está antes da construção do ABS.
Linha atual: ABS conceitual → pesquisa de capacidades → pesquisa Android → pesquisa de integração → recuperação do Sistema antigo → construção do Mini-Cérebro → aquisição do patrimônio histórico → ingestão → INVESTIGAÇÃO PROFUNDA DO CONTEÚDO HISTÓRICO → comparação com ABS → lacunas → pesquisa → arquitetura → construção do ABS.
Portanto, não pular diretamente para a construção.

## 26. Próxima operação
O próximo trabalho do Mini-Cérebro é investigar sistematicamente o patrimônio ingerido.
Primeiro: inventário interno → documentos → observações técnicas → código → relações.
Depois: identificar o conhecimento produzido durante a construção do Sistema e não apenas recuperar o software.

## 27. Resultado esperado
Sistema antigo → código + arquitetura + experimentos + observações + decisões + falhas + correções + resultados + descobertas → Mini-Cérebro → conhecimento histórico → Cérebro atual → comparação com ABS → manter/adaptar/reconstruir → arquitetura ABS.

## 28. Princípio final
O objetivo dos dois cérebros não é criar complexidade por si mesma.
É permitir que o Projeto Absoluto tenha memória do presente + memória do passado + evidência + capacidade de investigação + capacidade de execução.
O Mini-Cérebro olha para trás para recuperar conhecimento.
O Cérebro trabalha com o presente para compreender, decidir, planejar e executar.
O Imperador determina para onde o projeto deve ir.
O Projeto Absoluto transforma conhecimento em capacidade.
